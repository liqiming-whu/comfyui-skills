# Krea 2 Turbo 量化模型：Cold-ish 与 Warm Resident 对比

## 结论

本轮 Warm / Resident Model 测试共执行18次生成：每个量化模型先预热1次且不计成绩，再保持模型驻留并连续变更 seed 运行5次。18/18次执行成功，15/15次计分有效，没有 OOM；计分轮均有7个静态节点正常缓存，两个 KSampler、潜空间放大、VAE解码和保存链均未缓存。测试脚本全程未调用 `/free`。

NVFP4 在 Cold-ish 与 Warm 两种场景中都明显最快。模型驻留后，FP8 scaled 从 Cold-ish 中最慢变为略快于 MXFP8，但二者中位数只差0.290秒（约0.76%），可视为非常接近。

Warm模式下，以NVFP4为基准：MXFP8慢24.75%，FP8 scaled慢23.80%。FP8 scaled比MXFP8快0.76%，差距很小；若要确认这个微小差异是否稳定，需要随机交错顺序的更多重复测试。

## Warm测试协议

1. 按 NVFP4、MXFP8、FP8 scaled 的固定顺序测试。
2. 每组第1次运行负责切换、载入并预热模型，不计成绩。
3. 模型保持驻留，立即连续执行5次计分生成。
4. 每轮更改Seed节点中的整数seed，确保生成链重新执行。
5. 不调用 `/free`，不主动卸载模型，不清除内存缓存，不插入冷却等待。
6. 接受条件：`/prompt`无节点错误、history成功、输出非空、生成链无缓存节点。
7. 允许模型加载、文本编码器等7个静态节点缓存，这是Warm连续出图的预期行为。
8. 以0.1秒间隔采样ComfyUI进程RAM、整机RAM、整卡显存、GPU温度和功耗。

## 内存和显存边界

Warm计分阶段的最高整机RAM使用量分别为NVFP4 26.177 GiB、MXFP8 28.806 GiB、FP8 scaled 28.647 GiB；峰值时最低可用系统内存分别约为5.531 GiB、3.559 GiB和3.340 GiB。

Windows WDDM下，`nvidia-smi`对单个ComfyUI Python进程的显存返回`[N/A]`。因此这里报告的是0.1秒采样得到的整张GPU使用峰值，包含桌面和其他GPU进程，不能解释为ComfyUI独占显存。

绝对RAM峰值还会受到固定测试顺序、Python内存分配器和前一模型残留状态影响。Warm测试的核心指标是驻留后的执行时间；内存数据用于评估当前机器的实际安全余量，而不是模型权重的理论占用。

## 实际选择建议

- **本地连续创作：优先NVFP4。** 中位数30.588秒，速度优势明确，文件也最小。
- **需要FP8时：FP8 scaled略优于MXFP8。** 两者Warm速度基本同级，但本轮FP8 scaled中位数快0.290秒。
- **频繁切换模型或远程API：NVFP4优势更大。** 它的Cold-ish中位数比另外两种快约8.7至10.6秒。
- **不要从本次测试推导画质结论。** 本报告只比较执行性能、资源使用和稳定性；量化模型的图像质量需要使用固定seed和提示词另行盲评。
- **避免同时运行重型任务。** 三种模型虽均未OOM，但12 GB显存已接近满载，MXFP8/FP8 scaled的系统内存余量也不宽裕。
