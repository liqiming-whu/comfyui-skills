# 验收协议

## 文件检查

运行 `scripts/lint_captions.py`，依赖 Pillow。默认只读；只有显式 `--report` 才写指定 JSON，且路径必须位于数据目录之外。

| 等级 | 检查 |
|---|---|
| 错误 | 空目录、图文缺失、同名/大小写冲突、图片不可解码、caption 非 UTF-8 或有内部换行、完整触发词未出现或重复、明确的图片比例/画幅表述、用户显式禁止词、明确复制的镜像画面方向 |
| 告警 | 否定措辞、参数推断、tag 启发式、标点、英文词数、维度关键词覆盖、格式扩展名不符、不能从文字确认的镜像语义 |
| 信息 | 词数和关键词覆盖统计、跨 caption 的短语频次、镜像文字检查范围 |

退出码：普通模式错误时 1；严格模式错误或告警时 1；通过所选模式为 0；参数或报告写入失败为 2。

JSON 提供 `error_count`、`warning_count`、`strict`、`blocking_passed`、`passed`、`fail`、`warn`、`info`，以及触发词匹配方式 `trigger_match` 和比例/画幅检查范围 `frame_check_scope`。没有默认身份禁词；`--banned` 仅用于用户明确要求的其他文字约束。比例/画幅检查覆盖明确的中英文表述及常见数字形式，其他语言和表达仍需按同一规则人工语义复核，不能宣称正则已穷尽。景别与物件的长宽方向不属于图片画幅。

默认词数、语法和覆盖词表面向英文，按用户语言调整阈值；未命中不能报作图像属性缺失。无空格正文中的触发词可用 `--trigger-match literal`，同时核对完整字符串未被更长名称误包含。启发式告警不能代替图像质量判定，严格失败也不能成为自动改写准确事实的理由。

## 看图复核

新生成的接受样本和修改 caption 的图片逐张看图。大型已有数据集按风险抽样，并记录覆盖数与未核对范围；发现重复错误时扩大覆盖。

可先只看图写观察，再与 caption 对账。身份、方向、质感有分歧时回到图像确认；不能由两个观察者投票替代事实，不确定细节省略或粗化。

重点检查脸部、头位、视线、可控配饰、衣着、光位、虚实、背景物件；分辨图像实际实现了什么，而不是生成请求想得到什么。

镜像文字检查不验证像素翻转或对象语义，必须看图核对。可使用接触表辅助全集分布审计，细节判断仍检查单图。

人物制作按 [图像与分布审查](image-generation.md) 执行原始参考比较和分批验收。逐张记录接受、拒收或待核实及原因；新图不能凭相同发饰、服装或美观程度替代脸部身份检查。身份判断是视觉审核结论，有量化评分时另记方法与限制，不凭空编造人脸相似度。

每批对账计划与实际可见属性，累计只统计接受样本。最终复核用户指定的交叉配额、条件多样性、完全重复和近似重复、全部 caption 的准确性与比例/画幅规则。初始图文保留要求与验收标准有冲突时记录并核实，不把例外隐藏为通过。

## 训练后复核

按照 [训练与评估](training-evaluation.md) 保存固定条件样图与记录。至少覆盖身份保持、场景和属性变化、默认倾向、完整触发词/别名、无名称与无 LoRA 对照。

挂载 LoRA 后不写触发词也可能受权重影响，不能直接判为数据污染。风格变化时身份漂移有多个可能原因；单个失败例子不能直接归因于 caption 或训练集。

## 交付清单

- 正式数据集路径、图片与 caption 数、触发词或别名分配约定。
- 可重现的机器报告与独立的人工观察记录。
- 修订基线、图片哈希，以及新素材接受/拒收记录。
- 逐图制作计划与实际清单：文件名、原始/新增、用户指定类别与方向、视角、发型/配饰、服装、表情、动作、场景、光线、参考来源、批次、审核状态及图文哈希。按任务取舍字段，计划属性不冒充实际观察。
- 用户要求完整数据集时，正式图文、参考原件备份、清单、质量报告和预览分别存放；报告说明实际完成数量、配额、多样性、拒收重做、审核覆盖和未验证项，预览不进入训练目录。
- 训练配置与评估条件；未训练时明确素材验收的范围。
- 打包时核对 ZIP 条目清单、解压可读性、图文配对、文件数量与内容哈希；只将接受样本放入正式训练目录。caption 后续获准修改时同步同名副本、清单哈希、报告和压缩包，并确认图片字节未变。
