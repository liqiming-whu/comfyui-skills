# 本地训练与检查点评估

## 训练预检

读取用户指定的实际 config、当前日志和训练器版本/提交。日志陈旧时确认进程、文件更新时间和任务路径。配置或步数建议应以实际实现为依据。

AI-Toolkit 核对：

- 模型 `arch`、RAW/Turbo 基座、模型文件、文本编码器与 VAE 路径；分片权重所需索引是否齐全。
- 正式数据集路径、图片数量、caption 来源和触发词注入行为。
- `batch_size`、`gradient_accumulation` 及额外的累积设置；rank、alpha、学习率、优化器、训练步数与保存间隔。
- 分辨率列表、宽高比分桶、重复、过滤和增广。分辨率档与宽高比分桶是不同概念。
- `cache_text_embeddings`、caption dropout、文本编码器加载/卸载及缓存更新方式。修改 caption 或编码配置后，确认训练器按当前内容使用有效缓存；不盲目删除整个缓存目录。
- 训练中采样或独立推理评估任选可用流程。关闭内置采样可以保留检查点，在外部固定条件评估。

检查器只能校验数据文件，不能确认配置有效或模型真实启动。未执行训练不得报告训练通过。

## 指定图片增加训练次数

先区分目标：提高某些图片相对其他图片的采样频率，还是提高总训练量。以下方案调整采样分布；总 step 固定时，总样本消耗量不变。caption 中重复触发词不会改变采样次数。

本机 AI-Toolkit 的 `dataset.num_repeats` 把该数据集文件列表整体重复；多个数据集通过 `ConcatDataset` 合并。`network_weight` 用于训练时的网络倍率，不是图片采样权重。复用前核对实际版本的 `toolkit/config_modules.py`、`toolkit/data_loader.py` 和训练器的 `network.multiplier` 设置。

### 多个目录

- 普通与重点目录互不重叠，分别设置 `num_repeats: 1`、`num_repeats: 3`：重点图片相对普通图片约 3 倍。
- 完整目录设 1，再加载位于它外面的重点子集目录设 1：重点图片总倍率为 2。子集设 2 时总倍率为 3，计算时加上完整目录中的一次。
- 两个数据集条目的分辨率、caption、dropout 等其他条件保持一致，否则不再是只比较重复采样。

### 单目录与子目录

AI-Toolkit 使用 `os.walk` 递归读图；序号前缀和 `3_Ada` 之类的目录名不具有次数语义。单目录中用不同文件名保存真实副本，每份图片都有同名 TXT，caption 逐字复制。例如：

```text
train/
  selfie_001.png
  selfie_001.txt
  repeats/
    01_selfie_001.png
    01_selfie_001.txt
    02_selfie_001.png
    02_selfie_001.txt
```

只加载父目录，`num_repeats: 1`。原图加两份副本约为普通图片的 3 倍；只移动原图、加前缀或重命名目录不会增加次数。已经加载父目录时，不再单独加载 `repeats/`，否则副本额外计入。实际扫描跳过以点开头的目录和文件，且排除特定控制图片；选择重复目录前核对这些规则。

重复方案优先放入独立训练副本，保留正式数据集与原清单。记录原图到副本的映射、图片/TXT 哈希、唯一图片数、采样条目数及各图倍率。当前 linter 按文件名 stem 检查冲突，子目录中的副本仍使用全局唯一的 stem；lint 通过不等于验证了采样倍率。

若第 i 张独立图片的总倍率为 `r_i`，分辨率展开等其他因素一致且不考虑桶补齐，令 `W=sum(r_i)`、总样本消耗量为 `S×K`：

```text
第 i 张原图预期参与次数约为 S × K × r_i / W
两张原图的相对采样次数约为 r_i / r_j
```

例如 86 张独立图片中 10 张设总倍率 3，其他 76 张设 1，则 W=106，重点组占约 28.3% 的采样条目；相对普通图约 3 倍，但同 step 下相对原来均匀采样的绝对次数约为 2.43 倍。所有图统一增加 repeats，在固定 step 下不必然增加每张原图的预期次数。

重复也加强光照、服装、发饰、歪头及背景关联，不增加视觉多样性。少量高质量重点图可从总倍率 2 开始比较，不能把倍率当作保证身份改善的配方。

## 步数与数据遍历口径

用实际参与训练的样本数计算；不把文件总数自动当成有效样本数。设 S 为讨论的训练 step 数，K 为每 step 实际消耗的图片数，M 为训练器展开后的数据集样本数：

```text
数据集遍历次数约为 S × K / M
均匀采样时每张原图平均参与次数约为 S × K / N
```

对于单设备、batch=b、每个计数 step 取 G 个 batch、每张图按 R 个分辨率展开且无其他增广/过滤的情况，`K=b×G`、`M=N×R`。例如 S=1200、b=1、G=2、N=66、R=2，约 18.2 次展开数据集遍历、36.4 次原图参与。

多设备、额外累积、正则数据、重复、桶补齐、跳步或恢复训练时，以实际数据加载器和 step 定义修正口径。增加宽高比分桶不等于自动增加独立数据副本。不要把上述平均值解释为每张图恰好参与相同次数。

步数区间要结合学习率、rank、有效 batch、数据质量及样图；没有通用的“几十张图训练 1–2 epoch 即学完”结论。loss 可选择值得抽测的窗口，不可替代视觉身份排名。

## Caption dropout

按样本抽到时改变文本条件，图片仍参与训练，不等于浪费整个 step。若一次更新实际含 K 个独立抽取的样本，至少一个被丢弃的概率为 `1-(1-rate)^K`。

丢弃后的文本可能是空字符串，也可能保留训练器注入的触发词，必须核对当前实现及缓存分支。触发词只存在 caption 中且被一起丢弃时，可把 dropout=0 作为实验方案；不能承诺一定优于非零值，也不把所有 dropout 都称为完全无条件训练。

要归因时分别测试 caption、dropout、补图等变量；组合改动可以执行，但报告应说明无法拆分各项收益。

## ComfyUI API 工作流测试

对于已运行的本机 ComfyUI，优先使用 HTTP API，不为执行测试打开浏览器。从用户指定的 Base 工作流或已核验的 API 图开始，确认服务地址和 `/object_info` 中实际节点、输入及模型选项。默认端口 8188 只是候选，以运行实例为准。

画布 JSON 的 `nodes/links/widgets_values` 结构不能直接放到 `/prompt`。API 图是以节点 ID 为键的对象，每个节点包含 `class_type` 和 `inputs`，连线用 `[上游节点ID, 输出序号]`。优先使用现有 API 导出；需要从画布转换时，对照节点定义、连线和具名 widget 值逐项映射。不盲目按位置猜参数，也不把所有 bypass 节点当作无效画布控件直接删除；遇到缺失参数或无法判明的执行模式先解决再提交。

林知微案例的实际 Base 路径为 `E:/ComfyUI-aki-v3.2/ComfyUI/user/default/workflows/Krea2 Turbo Base Workflow.json`。其中 Fast Bypasser 只控制画布，转换时去除；实际生成链路保留。已成功执行的图在 [API 示例](../assets/Ada_step1000_Turbo_Base_API.json)，节点 ID 只适用于这份图，换工作流后重新定位。

执行与保存：

1. 读取 `/queue`，保留其他任务；无法隔离时等待，不清队列或中断别人的运行。列出检查点、提示词、种子、强度的任务清单，使用独立输出前缀。模型需要放入加载器可见目录时核对副本 SHA256。
2. 按实际运行环境替换模型文件名、LoRA、提示词、采样器使用的种子和输出前缀。不要只改一个未连入采样器的 seed 节点。比较检查点时保留其余参数及 conditioning 链路。
3. `POST /prompt` 的请求体为 `{"prompt": API图, "client_id": 本次任务标识}`。检查 HTTP 响应和 `node_errors`，记录 `prompt_id`。获得 ID 只证明已受理。
4. 查询 `/history/{prompt_id}`，按执行状态确认成功或错误，保存 history。暂时没有 history 不等于任务失败；结合本次 ID 的队列状态检查。设置合理的等待上限，超时或断连先查原任务状态，避免重复提交。执行错误保留诊断，不无限重试。
5. 按输出节点返回的 `filename/subfolder/type` 获取图片；本机可从对应目录复制，或用 `/view` 读取。保存实际提交的 API JSON、图片、任务清单、history、完整参数和模型哈希。有现成画布副本时可一并保存，不把画布文件代替 API 执行证据。

重复运行按完整条件和已核验输出识别完成项，不能只凭同一个文件名跳过。为别名实验保留同文本、同种子的无 LoRA 对照；可绕过加载器，或把 model/clip 强度都置 0 并记录做法。参数检查与人工看图结论分别交付。这里只规定测试方法，读取示例不授权自动重新运行整套任务。

## 固定条件评估与别名

记录基座文件/版本、LoRA 文件与 step、强度、文本编码器、VAE、采样器、步数、CFG、shift、分辨率、完整提示词和 seed。比较 step 时先固定其他条件；RAW 和 Turbo 的结论分别记录。无 LoRA 基线保持相同推理环境。

测试集覆盖：近景与全身、正面与侧面、端正头位、看向别处、新场景、不同光照、发型/配饰/服装变化。用多个固定 seed，分别记录身份保持和条件服从，不把全局亮度或边缘能量当成人脸相似度。

联合名称为 `林知微(Ada)` 时，用相同正文分别测试：

1. 完整名称 `林知微(Ada)`。
2. 中文别名 `林知微`。
3. 英文别名 `Ada`。
4. 不写名称、仍挂载 LoRA。
5. 同样提示词、不挂载 LoRA。

联合训练不保证别名单独有效。Ada 等常见名字可能已有语义；只能从这组受控结果判断当前模型的别名表现。挂载 LoRA 但无名称时出现相似人物也不自动构成训练事故。

林知微/Ada 已完成的一轮观察，以及 Xiaoling 项目的七组固定提示词，见 [实测案例与测试示例](checkpoint-examples.md)。参考已有结果选择抽测条件，不把历史结论当作新 checkpoint 的验收结果。

## 检查点选择

先筛选身份稳定且服从目标条件的候选，再比较细节与默认倾向。保存表现互有优势的相邻检查点；不要仅凭最低 loss 淘汰。没有样图时给出待评估的 step 范围，不宣布某 step 最优。
