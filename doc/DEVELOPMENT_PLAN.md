# 开发计划

## 目标

保持对 ComfyUI UI 工作流的精细创作控制，同时通过持续维护模板和模型推荐解决通用性问题。模板与模型说明共同构成本仓库的权威工作流基线；脚本负责确定性编辑和验证，不能用泛化说明替代实际资产。

## 当前环境

- 本机已安装 ComfyUI，可用于工作流导入、节点契约核对和真实推理测试。
- 本机环境作为当前实验平台，不将其模型路径、硬件结果或插件状态直接视为其他机器的通用结论。
- 后续计划逐步收集主流 Krea 2 社区版本；每个版本在下载和测试前分别核对来源、许可、文件标识、改动说明和运行依赖。

## 长期演进

当出现以下任一变化时，启动一次模板基线评审：

1. ComfyUI 源码、前端工作流格式或核心节点输入契约更新。
2. 自定义节点升级导致节点名称、插槽、控件或 API 序列化发生变化。
3. 开源社区出现经过广泛使用和持续验证的新模型。
4. 现有推荐模型明显落伍、停止维护、难以获得，或不再被主流工作流使用。

评审后应调整模板、模型说明和测试，使新建工作流默认采用仍有现实使用价值的方案。老模型不因“存在更新版本”立即删除；只有替代方案已成熟、主要任务覆盖完整、迁移路径明确时，才降低推荐等级或移除模板。

## 发布门槛

每次模板或推荐模型调整至少完成：

- 对照目标 ComfyUI 版本的 `/object_info`，确认节点类型和输入契约。
- 确认模型文件名、下载来源、许可证、目录和最低资源要求。
- UI JSON 解析、链接双向引用、节点/链接计数器和模型引用校验。
- 对受影响模板执行 UI 导入检查；可执行条件具备时完成一次真实任务。
- 需要 API 工作流时，在 ComfyUI WebUI 中选择“导出（API）”，并以目标实例的实际执行结果验证导出文件。
- 更新模型推荐的核验日期、状态和替代关系，不保留已经失效的旧名称。

## 模型推荐策略

推荐不是简单追逐最新版本，而是综合社区采用度、输出质量、显存需求、运行稳定性、许可证、模型可获得性和节点支持成熟度。模型分为：

- **默认推荐**：模板直接采用，适合大多数新工作流。
- **可选推荐**：特定质量、速度或硬件场景更合适。
- **兼容保留**：已有工作流仍常见，但不用于新模板。
- **淘汰**：下载或运行链路失效，或已被成熟替代方案全面取代。

模型名称必须区分展示名与可执行 ID。调用外部 API 的 UI 模板写供应商实际接受的 `model_name`；本地模型模板写实际文件名或运行时标签。无法实时确认时，不更新权威推荐。

## 当前重点

- 维护 Krea UI 工作流示例，核对模型依赖与目标节点契约。
- 收集具有代表性的主流 Krea 2 社区版本，区分官方权重、单纯量化、微调或其他优化类型，不以“社区版”作为统一行为标签。
- 在本机 ComfyUI 中使用相同提示词进行跨版本对照测试，记录不同版本的语义增益、边界遵循、构图稳定性、细节表现和资源开销。
- 维护 `comfyui_LLM_party` 模板及 OpenAI、Anthropic、DeepSeek、Ollama 推荐。
- 为模板建立分类型回归清单，并逐步补充真实 ComfyUI 导入和执行证据。
- 在性能 Skill 中积累不同硬件、缓存策略和工作流版本的可比较测量记录。
- 维护 `krea2-prompt-engineering` 的内容边界与语序条款，使提示词策略、承载句方向判定和年龄层级与实测结论保持同步。

## Krea 2 社区版本实测计划

### 样本与版本登记

为每个待测版本记录模型名称、作者或发布者、来源链接、许可证、文件名与校验值、版本日期、精度或量化格式、是否经过微调或其他优化、配套 VAE、文本编码器、LoRA 和所需自定义节点。作者没有明确说明的改动类型记为 `unknown`，不根据输出表现倒推训练方法。

优先覆盖社区采用度较高、改动说明相对清楚且能够在本机稳定运行的版本。官方 Krea 2 对应版本作为基线；同一模型的不同量化格式与不同微调版本分开登记。

### 对照条件

- 建立覆盖人像、材质、构图、文字、局部形态和边界约束的固定提示词集；每次比较使用完全相同的提示词文本。
- 尽可能固定分辨率、seed、采样器、调度器、步数、引导参数、文本编码器、VAE、LoRA 和工作流结构。
- 模型必须使用特定 VAE 或参数时，记录为“完整配置组合比较”，不把差异单独归因于 checkpoint。
- 单个固定 seed 用于定位差异，再用多个固定 seed 检查现象是否可复现；不同模型的同一 seed 不等同于相同潜空间结果。
- 首轮不为某个版本单独改写提示词。完成同提示词比较后，再建立该版本的提示词校准轮次，并与基线结果分开保存。

### 观察与记录

逐项记录主体和场景一致性、核心语义强度、边界条件遵循、空间与构图、材质和细节、文字渲染、伪影、运行时间及显存占用。对于“更听提示词”等判断，拆分为可观察的语义增益和边界遵循，不用单张图概括模型的全局能力。

每次实验保留完整提示词、工作流、参数、seed、模型标识、输出图和测试日期。结论标注适用的版本、题材、配置与样本范围；单次现象记为暂定观察，经过多 seed 或重复测试后再提高置信度。

### 阶段交付

1. Krea 2 版本与依赖清单。
2. 固定提示词测试集和可复现工作流。
3. 每个版本的逐项结果记录及配对输出。
4. 官方版与社区版本的对照总结。
5. 经重复验证后，更新 `krea2-prompt-engineering` 的模型画像和提示词策略；未经验证的观察不升级为默认规则。

> 第 5 项已于 2026-09-22 完成首轮落地（依据官方 Krea 2 Turbo 的 3 seed 分档实验）。逐条见「变更记录」。审阅中的变更仍按本节门槛执行，未复现的观察不下沉为默认规则。

## 不纳入自动更新的事项

- 不因模型发布公告自动下载模型或覆盖用户文件。
- 不根据未经验证的排行榜或单次演示替换默认模板。
- 不在缺少目标节点契约时猜测自定义节点输入。
- 不把个人 API 密钥、绝对本机路径或付费服务配置写入模板。
